在 Ubuntu 22.04 的 ROS 2 Humble 环境中启动插件附带的桥节点 `ubot_ros_bridge`，并验证 UE 与桥的连接。

## 步骤

<Steps>

1. **准备环境**

   桥已在 Ubuntu 22.04 的 ROS 2 Humble 环境中验证。UE 运行在 Windows 上时，可将 ROS 2 安装到适用于 Linux 的 Windows 子系统（WSL）的 `Ubuntu-22.04` 发行版中，安装见 [ROS 2 Humble 官方文档](https://docs.ros.org/en/humble/Installation.html)。

   桥仅依赖 Python 标准库、`rclpy`、`rosidl_runtime_py` 和以下消息包，不需要 colcon 和 C++ 编译器：

   - `builtin_interfaces`、`std_msgs`、`geometry_msgs`、`nav_msgs`
   - `sensor_msgs`、`tf2_msgs`、`rosgraph_msgs`

   桥只加载 ament 索引里已安装的消息接口，用到自定义消息时，应先通过 `source` 加载对应工作空间的环境配置。

2. **找到桥的源码**

   桥在插件的 `ros2/ubot_ros_bridge` 文件夹里，即 `<Project>/Plugins/uBot/uBotROS/ros2/ubot_ros_bridge`。下文把 `<Project>/Plugins/uBot/uBotROS` 写作 `<UBotROS 插件>`。

   在 WSL 里，Windows 的磁盘挂在 `/mnt/` 下，例如 `E:\MyProject` 对应 `/mnt/e/MyProject`。

3. **启动桥**

   直接以 Python 模块运行，无需通过 colcon 构建（该方式已经验证）：

   ```bash
   source /opt/ros/humble/setup.bash
   cd <UBotROS 插件>/ros2/ubot_ros_bridge
   python3 -m ubot_ros_bridge.bridge_node --port 8268
   ```

   或者把包复制（或软链接）到 colcon 工作空间并构建：

   ```bash
   mkdir -p ~/ubot_ws/src && cp -r <UBotROS 插件>/ros2/ubot_ros_bridge ~/ubot_ws/src/
   cd ~/ubot_ws && colcon build --packages-select ubot_ros_bridge && source install/setup.bash
   ros2 run ubot_ros_bridge bridge --ros-args -p port:=8268
   ros2 launch ubot_ros_bridge ubot_ros_bridge.launch.py port:=8268
   ```

   上述 `ros2 run` 和 `ros2 launch` 命令任选其一执行。桥启动后打印 `ubot_ros_bridge 0.1.1 listening on 0.0.0.0:8268 (ROS humble, ...)`，按 `Ctrl+C` 退出。

4. **设置 UE 的地址**

   桥和 UE 在同一台机器上，包括 Windows 上的 UE 连 WSL 里的桥时，`Bridge Host` 保持默认的 `127.0.0.1`，`Bridge Port` 保持 8268，无需修改。其他网络部署方式见下面的“WSL 与网络”。

5. **运行并确认**

   在 UE 中点击「Play」。`Auto Connect` 默认开启，世界开始时自动连接，UE 的输出日志（`LogUBotROS`）里出现 `uBot ROS bridge: connected to 127.0.0.1:8268`。

   在 ROS 2 终端中查看 `/clock`；该话题无需添加传感器即可发布：

   ```bash
   ros2 topic echo /clock --once
   ```

</Steps>

### WSL 与网络

- **Windows 上的 UE，WSL 里的桥**：`Bridge Host` 保持默认的 `127.0.0.1`。WSL2 的 localhost 转发把 Windows 的 `127.0.0.1:8268` 转到 WSL 里的桥；在 NAT 网络模式、`localhostForwarding=true` 下，桥监听默认的 `0.0.0.0` 和 `--bind-address 127.0.0.1` 两种情况都验证过。
- **ROS 在另一台机器上**：把 `Bridge Host` 设成那台机器的地址，桥保持默认的 `0.0.0.0` 监听，并在防火墙上放行 TCP 8268。
- **机器可能被不可信网络访问**：桥用 `--bind-address 127.0.0.1`，或用防火墙限制来源，见下面的注意事项。

## 关键属性

桥支持通过命令行选项、ROS 参数（`--ros-args -p 名称:=值`）或 launch 文件配置，ROS 参数的优先级更高。下表列出常用参数：

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `bind_address` | `0.0.0.0` | 监听地址 |
| `port` | 8268 | 监听端口，需与 UE 的 `Bridge Port` 一致 |
| `max_payload_bytes` | 64 MiB | 单帧负载上限，需与 UE 的 `Max Payload Bytes` 一致 |
| `max_queued_bytes` | 128 MiB | 每个客户端的发送队列上限，队列满时先丢 best_effort 消息 |
| `idle_timeout_seconds` | 10 s | 客户端在该时间内未发送任何数据时，桥断开连接；0 表示关闭 |
| `max_clients` | 32 | 同时接受的客户端数，一个 Game 或 PIE 世界占一个；0 表示不限制 |

每个参数都有同名的命令行选项，下划线写成连字符，例如 `--max-payload-bytes`。其余参数（`hello_timeout_seconds`）和 launch 参数见[桥的 README](https://github.com/AstreoX/uBotROS/blob/main/ros2/ubot_ros_bridge/README.md)。

## 输出与事件

桥和 UE 都会在日志中报告连接过程。桥在终端里打印：

- `listening on 0.0.0.0:8268`：桥已经在监听，UE 应配置为该监听地址可达的主机地址，并使用相同端口。
- `advertised /robot1/imu/data [sensor_msgs/msg/Imu]`：UE 声明了一个发布者，桥创建了对应的 ROS 2 话题。
- `disconnected: <原因>`：一个客户端断开，桥释放了它的全部话题。

UE 在输出日志（`LogUBotROS`）里打印：

- `connected to 127.0.0.1:8268 (ubot_ros_bridge 0.1.1, ROS humble)`：握手完成。
- `ROS sensor bridge '...' on '...' ready: namespace '/robot1', N sensor(s), M topic(s)`：一个 Sensor Bridge 组件已完成发布器的创建。

添加 Sensor Bridge 后，在 ROS 2 中用下面的命令查看（`robot1` 是示例命名空间）：

```bash
ros2 topic list
ros2 topic echo /robot1/imu/data --once
ros2 topic hz /robot1/imu/data
ros2 topic echo /tf_static --once --qos-durability transient_local --qos-reliability reliable
ros2 run tf2_ros tf2_echo base_link imu_sensor
ros2 topic pub -r 10 /robot1/cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.5}, angular: {z: 0.2}}"
```

最后一行向 UE 发送 `cmd_vel` 指令，需要 Actor 上有 `uBot ROS Velocity Command`，见[接收 cmd_vel](/ros/cmd-vel/)。

## 注意事项

- 协议没有认证和加密，任何能连上端口的人都能让桥发布和订阅话题。桥默认监听 `0.0.0.0`，在可能被不可信网络访问的机器上请用 `--bind-address 127.0.0.1` 或防火墙。
- 桥进程的 `ROS_DOMAIN_ID` 决定话题出现在哪个 ROS 域里，ROS 2 终端应使用相同的 `ROS_DOMAIN_ID`。
- 传感器话题是 best_effort，`ros2 topic echo` 会自动适配；编写订阅者或在 RViz 中显示时，把 QoS 设为 best_effort。
- 没有订阅者的话题默认不编码、不发送，所以 `ros2 topic list` 里有话题，不代表 UE 一直在发数据。
- colcon 方式的包描述是完整的，但尚未在测试环境中执行验证；只验证了 ROS 2 Humble。
- 端口被占用时，桥打印错误并以退出码 1 结束。
