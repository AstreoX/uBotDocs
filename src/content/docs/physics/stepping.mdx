后端在每帧的指定阶段执行仿真步进并更新组件位姿，单帧所需步数超过上限时会跳过部分步进。

后端的步进和位姿回写发生在每帧的 `TG_PrePhysics`，游戏暂停时不运行：

| 阶段 | 发生了什么 |
| --- | --- |
| `TG_PrePhysics` | 按需扫描场景；各求解器接收场景更新，并按各自固定步长推进至不超过当前仿真时间的最近步进时刻；所有求解器完成步进后，将绑定物体的位姿更新到对应组件 |
| `TG_DuringPhysics` | Chaos 模拟其余的物体，被绑定的组件作为运动学体推动它们 |
| `TG_PostPhysics` | 传感器采样、ROS 发布 |

## 步进

每个求解器有自己的固定步长，范围 0.0001 s 到 100 s。

- 求解器开始持有物体后，子系统首次运行时启动该求解器的时钟。第一步的结束时间为启动时间加一个固定步长，后续各步的结束时间依次增加一个固定步长。
- 求解器时间始终不超过当前仿真时间；暂停期间停止步进，恢复后不会补执行暂停期间的步进，见[仿真时钟与采样调度](/concepts/clock-and-scheduling/)。
- 求解器的全部物体解绑后，该求解器停止步进；再次绑定物体时，其时钟重新启动。
- 单帧内可能执行多个物理步，也可能因累计时间不足一个固定步长而不执行物理步。即使该帧没有执行步进，子系统仍会更新组件位姿，并按场景更新规则发送更新。

## 丢步

丢步是指单帧所需物理步数超过每帧上限（默认 1000）时，求解器仅执行时间顺序最早的允许步数，其余物理步被跳过，之后也不会补执行。跳过的步数用 [`Get Dropped Physics Steps`](/reference/ubotphysics/uubotphysicslibrary/#GetDroppedPhysicsSteps) 查询，计数大于 0 表示物体实际执行的模拟时长少于仿真时间的推进量。

```blueprint
caption: 每个 Tick 显示某个后端累计丢弃的步数
nodes:
  T: AActor.ReceiveTick
  G: { ref: UUBotPhysicsLibrary.GetDroppedPhysicsSteps, set: { Backend: MyBackend } }
  S: UKismetStringLibrary.Conv_Int64ToString
  P: UKismetSystemLibrary.PrintString
wires:
  - T.then -> P.execute
  - G.ReturnValue -> S.InInt
  - S.ReturnValue -> P.InString
notes:
  G: "`Backend` 填后端名，这里的 `MyBackend` 只是示例。"
```

- 单帧耗时过长或后端固定步长过短，都可能使所需步数超过上限。
- 跳过的物理步数在当前世界的生命周期内累计，不会清零。
- 每帧上限在 C++ 里用 `UUBotPhysicsSubsystem` 的 `GetMaxStepsPerFrame` 和 `SetMaxStepsPerFrame` 读写，默认 1000，至少为 1。

## 位姿回写

- 位姿回写是指将后端计算的位姿更新到 UE 组件；更新使用最近一个完整物理步的结果，不进行外推：没有丢步时，组件的位姿落后仿真时间最多一个步长。
- 跳过物理步后，位姿相对仿真时间的延迟可能超过一个步长。被跳过的步不会补执行，累计少执行的模拟时长为跳过步数乘以步长，直到求解器时钟重新启动。
- 更新组件位姿时，子系统按附着关系先更新父组件、再更新子组件，即使两者属于不同后端也遵循此顺序。因此，父子组件均已绑定时，子组件的最终位姿以其所属求解器的结果为准。
- 后端返回的状态包含非有限值时，子系统不会更新该物体的组件位姿，组件保留上一次有效位姿。
