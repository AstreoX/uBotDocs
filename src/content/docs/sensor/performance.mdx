了解各 uBot 传感器每次采样的工作量和开销高的节点，以便选择合适的采样频率。

| 传感器 | 每次采样做什么 | 工作量随什么增长 |
| --- | --- | --- |
| 位姿、里程计、IMU | 读取组件变换并进行差分计算（0.1.2 起，机体具有刚体状态源时，相关运动量改为从状态读取）；IMU 另有噪声、滤波和限幅 | 固定，只有少量向量运算 |
| 2D 激光雷达 | `Horizontal Samples` 次射线检测，默认 541 次 | 射线数，范围 2 到 4096 |
| 3D 激光雷达 | `Number Of Channels` × `Horizontal Samples` 次射线检测，默认 16 × 360 = 5760 次 | 射线数，上限由 `Maximum Rays Per Scan` 给出，默认 65536 |
| RGB 相机 | 把场景渲染一次到渲染目标（Render Target） | 分辨率（默认 640 × 480，每边 16 到 4096）和场景复杂度 |
| 深度相机 | 同 RGB 相机，渲染到采用深度格式的渲染目标 | 同 RGB 相机 |

采样在组件的更新函数（Tick）中触发。激光雷达的射线检测在游戏线程上依次同步执行，耗时直接计入帧时间。相机每次采样会让引擎多渲染一次场景。

## 激光雷达

- 3D 激光雷达的射线数超过 `Maximum Rays Per Scan` 时，这次扫描报错，不会截断。
- `Trace Complex` 默认关闭，射线只与简单碰撞求交。开启后，单条射线的检测开销更高。
- `Enable Smoke Interference` 默认打开：每次采样都需要收集场景中的介质，接口路径和旧版标签路径分别遍历世界中的所有 Actor（旧版标签路径查找带有 `Smoke Volume Actor Tag` 标签的烟雾 Actor）。不需要烟雾干扰时，可关闭该属性。
- `Debug Visualization` 每次采样画调试线，2D 激光雷达约 32 条，3D 激光雷达最多 128 条。正式运行时应关闭该属性。
- 每秒射线数是采样频率乘以每次的射线数：默认的 2D 激光雷达是 541 × 10 = 5410 条，3D 激光雷达是 5760 × 10 = 57600 条。

## High Cost 节点

名称中带有 `(High Cost)` 的节点每次调用都会返回整个数组的副本，处理开销随数组规模增大。仅需少量数据时，应使用按索引或坐标读取的节点：

| 数据 | High Cost 节点 | 读单个值用 |
| --- | --- | --- |
| 2D 激光雷达帧 | `Copy All Ranges`、`Copy All Hit Flags` | `Get Range by Index`、`Get Sample Count` |
| 点云帧 | `Copy All Points`、`Copy All Ring Indices`、`Copy All Time Offsets`、`Copy All Intensities` | `Get Point by Index`、`Get Point Count` |
| 图像帧（RGB） | `Copy Pixel Bytes` | `Get BGRAPixel by Coordinates` |
| 图像帧（深度） | `Copy Depth Values` | `Get Depth Meters by Coordinates` |

数组规模如下：一帧 2D 扫描默认 541 个值；3D 激光雷达的点云不会超过 `Maximum Rays Per Scan`（默认 65536）个点；深度相机的 `Generate Point Cloud` 为每个有效像素生成一个点，640 × 480 最多 307200 个。一帧 640 × 480 的图像有 307200 个像素。

## 相机读回

相机每次采样都会渲染一次场景，但不会把像素读回 CPU。图像保存在 GPU 的渲染目标（Render Target）中，帧对象 `UBot Image Frame` 仅持有对该渲染目标的引用。

需要访问像素时，应调用 `Request Pixel Readback`。该操作同步执行，具有较高开销：

- 读回操作需要等待渲染完成，在游戏线程上阻塞。
- 只能读最新一次采集的帧。渲染目标被后续采集覆盖后，旧帧读回会返回错误。
- 帧上已有像素数据时，再次调用直接返回成功，不会重复读回。
- 读回的像素占 CPU 内存：BGRA8 和深度每个像素都是 4 字节，640 × 480 的一帧是 1228800 字节，1920 × 1080 的一帧是 8294400 字节。使用完毕后调用 `Clear CPUPixel Data` 释放。
- 烟雾叠加发生在读回时，介质存在时要对每个像素求交，不影响渲染目标本身。
- `Update Depth Preview` 和 `Generate Point Cloud` 都要遍历整帧像素；前者在没有像素数据时会先读回。

应仅对需要访问像素的帧执行读回，其余情况下仅使用帧头和相机内参。

## 采样频率

| 传感器 | 默认频率 | 要注意 |
| --- | --- | --- |
| 位姿 | 30 Hz | 没有特别的限制 |
| 里程计 | 30 Hz | 不要低于 2 Hz，否则间隔超过 `Maximum Valid Delta Seconds`（0.5 s），每个样本都无效 |
| IMU | 100 Hz | 不要低于 2 Hz，采样间隔同样受最大有效间隔限制；帧率低于 100 帧/s 时，实际频率等于帧率 |
| 2D 激光雷达 | 10 Hz | 开销随射线数和频率成正比 |
| 3D 激光雷达 | 10 Hz | 开销随射线数和频率成正比 |
| RGB 相机 | 30 Hz | 每个采样时刻渲染一次场景 |
| 深度相机 | 30 Hz | 每个采样时刻渲染一次场景 |

- `Update Rate Hz` 的范围是 0.1 到 240 Hz，「Details」面板的滑块到 120 Hz。
- 每个世界更新周期（World Tick）最多采集一个样本，所以采样频率不会超过帧率。超出每帧处理能力的采样时刻会被跳过，不会补采。
- 暂停时不自动采样。
- 建议以各传感器的默认值作为初始配置，再根据所需数据量和性能测量结果调整。

## 怎么发现跟不上

`Get Dropped Sample Count` 返回被跳过的采样次数。计数不为 0 表明部分帧的持续时间超过采样间隔，传感器未能按设定频率完成全部采样：

```blueprint
caption: 每个 Tick 打印一次被跳过的采样次数
nodes:
  E: AActor.ReceiveTick
  V: { var: Lidar, class: UUBot3DLidarSensorComponent }
  G: UUBotSensorComponent.GetDroppedSampleCount
  S: UKismetStringLibrary.Conv_Int64ToString
  P: UKismetSystemLibrary.PrintString
wires:
  - V.Lidar -> G.Target
  - G.ReturnValue -> S.InInt
  - S.ReturnValue -> P.InString
  - E.then -> P.execute
```

- 计数在每次 `Start Sensor` 时清零。
- 3D 激光雷达的帧里还有 `Capture Duration Milliseconds`，表示本次扫描耗时，单位 ms。
- 相机协调器单独提供 `Get Dropped Capture Count`，见[相机采集协调器](/sensor/capture-coordinator/)。
