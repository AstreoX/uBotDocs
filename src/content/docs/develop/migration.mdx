从旧插件迁移到 uBot 时，插件自带的重定向（CoreRedirects）可自动处理部分资产引用，其余组件配置和 C++ 引用需要手动调整。

| 旧插件 | 替代方案 | 资产中的旧引用 |
| --- | --- | --- |
| `AgentSensorCore` | uBotSensor，帧头和状态枚举移到 uBotCore | 自动重定向 |
| `AgentSensorROSBridge` 的 `Agent ROS Sensor Suite Publisher` | uBotROS 的 `uBot ROS Sensor Bridge` | 自动重定向 |
| `AgentVehicleROSBridge` 的 `Agent ROS Vehicle Command` | `uBot ROS Velocity Command`，并由车辆实现 `IUBotVelocityCommandable` | 手工替换组件 |
| `AgentDroneROSBridge` 的 `Agent ROS Drone Command` | 同上，由无人机实现 `IUBotVelocityCommandable` | 手工替换组件 |
| TempoROS | 不再需要，启动随 uBotROS 附带的 `ubot_ros_bridge` | 不适用 |

重定向仅处理资产中序列化的数据；引用旧名称的 C++ 代码需要手动更新。

## AgentSensorCore 到 uBotSensor

`UFUNCTION` 和 `UPROPERTY` 的名称保持不变，因此蓝图中的引脚在类重定向之后继续有效。

<Steps>

1. **安装 uBotSensor**

   通过 uBot Manager 安装 `UBotSensor`，Manager 会同时安装缺失的 `UBotCore`，见[安装、更新、移除插件](/manager/packages/)。

2. **禁用 AgentSensorCore**

   新旧同时启用时，uBot Manager 和编辑器的 uBot 面板（「Problems」分区）都会报告冲突。应禁用旧插件以消除冲突。

3. **重启编辑器**

   重定向只在编辑器启动时加载。在正在运行的编辑器中启用 uBotSensor，旧资产不会被重定向。

4. **重新保存资产**

   打开并保存引用旧传感器的蓝图和关卡，使其按新名称重新序列化。

5. **改 C++ 代码**

   按下表更新名称，并在 `Build.cs` 中同时添加 `UBotSensor` 和 `UBotCore`。

6. **移除旧插件**

   确认相关资产可正常加载和运行后，从项目中移除 `AgentSensorCore`。

</Steps>

蓝图中的显示名称也随之变更：组件由 `Agent IMU Sensor` 变为 `uBot IMU Sensor`（其余同理），「Details」面板中的类别「Agent Sensor」变为「Sensor」，函数类别加前缀「uBot Sensor」，插件分类由「Simulation」变为「uBot」。

### C++ 里的改名

| 旧名称 | 新名称 |
| --- | --- |
| `UAgentImuSensorComponent` 等 `UAgentXxx` 类 | `UUBotImuSensorComponent` 等 `UUBotXxx`；文件 `AgentXxx.h/.cpp` 改为 `UBotXxx.h/.cpp` |
| `FAgentPoseSensorData`、`FAgentImuSensorData`、`FAgentOdometrySensorData` | `FUBotPoseSensorData`、`FUBotImuSensorData`、`FUBotOdometrySensorData` |
| `EAgentPoseReferenceFrame`、`EAgentImageEncoding`、`EAgentDepthPreviewMode` | `EUBotPoseReferenceFrame`、`EUBotImageEncoding`、`EUBotDepthPreviewMode` |
| `FAgentSensorFrameHeader`、`EAgentSensorSampleStatus` | `FUBotFrameHeader`、`EUBotSampleStatus`，移到 uBotCore（`UBotTypes.h`），字段和枚举值不变 |
| 动态委托 `FAgent…Event` | `FUBot…Event` |
| `AgentSensorMath` | `UBot::SensorMath`；`WorldCentimetersToMeters` 已删除，改用 `UBot::Units::CentimetersToMeters` |
| `AgentSensorSmoke` | `UBot::SensorMedium` |
| `AgentLidarVisualizer`（编辑器模块） | `UBot::LidarVisualizer` |
| 模块 `AgentSensorCore`、`AgentSensorCoreEditor` | `UBotSensor`、`UBotSensorEditor`；导出宏 `AGENTSENSORCORE_API` 改为 `UBOTSENSOR_API` |
| 日志类别 `LogAgent*` | 合并为 `LogUBotSensor` |
| 网格 `SM_AgentSensor_<Kind>`，路径 `/AgentSensorCore/Models/` | `SM_UBotSensor_<Kind>`，路径 `/UBotSensor/Models/` |

### 行为差异

除名称变更外，未列出的行为与旧版保持一致。以下为已明确调整的行为：

| 项目 | 变化 |
| --- | --- |
| 采样调度 | 旧版使用循环 `FTimerManager` 定时器，单帧耗时超过采样间隔时会在同一帧触发多次，导致多个样本使用相同仿真时间，IMU 和里程计因而报告 `InvalidDeltaTime`。当前版本通过组件 tick 和 `FUBotSampleScheduler` 驱动，每个 world tick 最多一个样本，跳过的间隔计入 `GetDroppedSampleCount()` |
| 时间戳 | 取自 `UBot::Clock::GetSimTimeSeconds`，时间基准与旧版相同 |
| 强度 | 2D 激光雷达帧和点云帧各新增 `GetIntensities()`，范围 0 到 255 |
| 枚举传感器 | 所有传感器实现 `IUBotSensor`，可以用 `UBot::Sensors::FindSensors` 统一枚举；C++ 中新增虚函数 `GetSensorTypeName()` |
| 烟雾 | 基于 uBotCore 的 `UBot::Medium`，新增 `IUBotPerceptionMedium` 发现路径。Actor 标签 `AgentSensor.SmokeVolume` 的旧路径行为不变，应保留该标签名称 |

## 旧 ROS 桥到 uBotROS

<Steps>

1. **启动新的桥**

   不再需要 TempoROS 和 rclcpp，UE 一侧也没有第三方依赖。在 ROS 2 端启动 `ubot_ros_bridge`，见[准备 ROS 2 端](/ros/ros2-setup/)。

2. **安装 uBotROS，禁用旧插件**

   uBotROS 依赖 uBotCore 和 uBotSensor。目前的索引只登记了 `AgentSensorCore` 的替代关系，所以 `AgentSensorROSBridge`、`AgentVehicleROSBridge` 和 `AgentDroneROSBridge` 需要在「Edit > Plugins」中手动禁用。

3. **重启编辑器并重新保存资产**

   `Agent ROS Sensor Suite Publisher` 组件会重定向为 `uBot ROS Sensor Bridge`，它的属性、结构体、枚举和事件一起重定向。蓝图的函数名和事件名不变，引脚继续有效。

4. **检查命名空间**

   旧属性 `RobotNamespace` 默认为 `robot`，新属性 `RobotNamespaceOverride` 默认为空，表示采用 uBot Identity 解析的命名空间。若需要保留旧话题名称，应显式填写 `RobotNamespaceOverride`，或为机器人添加 `uBot Identity` 并设置 `Namespace`，见 [Identity 组件](/core/identity/)。

5. **替换速度指令组件**

   `Agent ROS Vehicle Command` 和 `Agent ROS Drone Command` 不提供重定向：移除旧组件，添加 `uBot ROS Velocity Command`，并让车辆或无人机实现 `IUBotVelocityCommandable`，见[在 C++ 中使用传感器与接口](/develop/cpp/)和[接收 cmd_vel](/ros/cmd-vel/)。旧组件中的比例速度控制器、油门、制动、转向映射和失效制动不由 uBotROS 提供，需要由指令目标对象实现。

6. **检查 ROS 侧的消费者**

   输出数据包含下表列出的修正，应检查 ROS 端数据使用方是否依赖旧行为。

</Steps>

### 输出数据的修正

| 项目 | 旧版 | 现在 |
| --- | --- | --- |
| 角速度符号 | Odometry 的 `twist.angular` 和 IMU 的 `angular_velocity` 当作普通向量，用 `(x, -y, z)` | 角速度属于轴向量，采用 `(-x, y, -z)`：UE 中向右偏航转换为 ROS 中负的 Z 角速度。Odometry 的 6×6 协方差按镜像 `diag(+,-,+,-,+,-)` 调整符号 |
| LaserScan | 角度和距离原样发布，扫描是镜像的，强度被清空 | 角度按 ROS 约定镜像（`angle_min`、`angle_max` 对调并取反），`ranges` 和 `intensities` 倒序，未命中为 `+inf`，帧中存在强度数据时同时发布 |
| PointCloud2 | `point_step = 18`，没有强度 | 增加 `intensity`（float32，偏移 12），`ring` 在 16，`time` 在 18，`point_step = 22`。按 `fields` 中的偏移读取数据的使用方不受影响，硬编码偏移的读取代码需要更新 |
| 相机坐标系 | Image 和 CameraInfo 使用相机自身的坐标系，没有光学坐标系（optical frame）的 TF | 使用 `<frame>_optical`，并发布静态 TF `<frame> -> <frame>_optical` |
| 里程计的静态 TF | 里程计传感器也发布静态 `base_link -> frame`，与动态 `odom -> base_link` 成环 | 里程计传感器没有静态 TF |
| `/tf_static` | 每个组件通过自己的 ROS 节点各自发布 | 所有组件合并成一条锁存（latched）消息，变化时和重连后重新发布 |

位置和四元数的映射与旧版相同，默认话题路径、逻辑键、校验规则和蓝图 API 保持不变。

如果安装过早期版本的 uBotROS，还需要迁移项目设置：早期版本使用项目的 `Config/DefaultEngine.ini`，当前版本只读取 `Config/DefaultUBotROS.ini`。应将 `[/Script/UBotROS.UBotROSSettings]` 整段移动到新文件，或在「Project Settings」中重新配置。

## 风场从 uBotAerial 迁到 uBotEnvironment（开发版）

这次拆分属于尚未发布的开发版：uBotAerial 0.1.2、uBotEnvironment 0.1.0 和 uBotCore 0.1.4，不能通过 uBot Manager 安装。已发布的 uBotAerial 0.1.1 继续使用自身模块中的风场，无需执行此项迁移。

风源 Actor、风子系统和设置结构体迁移到新模块，类名、属性、函数和默认值保持不变；恒定风、阵风和多风源叠加的行为保持不变。

| 类型 | 旧序列化路径 | 新序列化路径 |
| --- | --- | --- |
| `AUBotWind` | `/Script/UBotAerial.UBotWind` | `/Script/UBotEnvironment.UBotWind` |
| `UUBotWindSubsystem` | `/Script/UBotAerial.UBotWindSubsystem` | `/Script/UBotEnvironment.UBotWindSubsystem` |
| `FUBotWindSettings` | `/Script/UBotAerial.UBotWindSettings` | `/Script/UBotEnvironment.UBotWindSettings` |

<Steps>

1. **启用 uBotEnvironment 并重启编辑器**

   在本地源码工程中同时更新上述三个插件。旧蓝图或关卡引用了风 Actor、风子系统或风设置时，需要启用 uBotEnvironment，再重启编辑器，使新插件的重定向生效。

2. **检查并重新保存旧资产**

   打开含风源的旧关卡、使用风节点或风设置变量的蓝图，确认参数和节点连线后重新保存。旧版 `L_UBotAerialDemo` 中保存的风 Actor 同样需要启用 uBotEnvironment；新版示例地图已移除这个默认关闭的 Actor，可独立使用。仅使用无人机且不引用风相关资产的项目，无需启用 uBotEnvironment。

3. **调整直接使用风场的 C++ 模块并重新编译**

   在使用风 Actor、风子系统或风设置的模块 `Build.cs` 中加入 `UBotEnvironment`。`UBotWind.h` 和 `UBotWindSubsystem.h` 文件名不变；`FUBotWindSettings` 的头文件由 `UBotAerialTypes.h` 改为 `UBotEnvironmentTypes.h`，修改后重新编译，旧二进制不能直接复用。

</Steps>

重定向位于 uBotEnvironment 的 `Config/DefaultUBotEnvironment.ini`，只覆盖上表的两个类和一个结构体。它处理资产序列化引用；C++ 的模块依赖和头文件仍需按步骤修改。

无人机的 `Enable Wind`、阻力系数和抗风响应继续由 uBotAerial 管理。飞行模型经 Core 查询风速，没有提供者时返回零；uBotAerial 不依赖 uBotEnvironment，uBotEnvironment 也不依赖 uBotAerial。

## CoreRedirects

重定向（CoreRedirects）列表分别保存在插件自带 `Config/` 配置文件的 `[CoreRedirects]` 段，引擎在配置已启用的插件时加载。每条重定向将旧类、结构体、枚举、委托签名或资产路径映射到新名称，使旧资产能够在加载时解析对应引用。

| 插件 | 文件 | 条数 | 内容 |
| --- | --- | --- | --- |
| uBotSensor | `Config/DefaultUBotSensor.ini` | 47 | 脚本包 1，类 14，结构体 4，枚举 4，动态委托签名 10，网格 14（包 7、对象 7） |
| uBotROS | `Config/DefaultUBotROS.ini` | 11 | 脚本包 1，类 1，属性 2，结构体 2，枚举 2，动态委托签名 3 |

- 重定向只在编辑器启动时生效。在正在运行的编辑器中启用插件，旧资产不会被重定向，请重启编辑器。
- 重定向只处理序列化数据。引用 `UAgent*` 等旧名称的 C++ 代码需要手动更新名称。
- 旧资产第一次打开后请重新保存，使其按新名称重新序列化。
- `FAgentROSQOSOverride`（`bOverride`、`Reliability`、`QueueSize`）变成 `FUBotROSQosOverride`（`bOverride`、`Qos`）：旧字段值在加载后迁移到 `Qos.Reliability` 和 `Qos.Depth`。启用覆盖时，日志会输出一条 `Migrated a legacy QoS override` 警告，重新保存资产后按新格式存储。
- `NodeNameOverride` 不再提供对应的新属性，因为当前实现不再为每个组件创建独立 ROS 节点；旧配置值会被忽略。
- 插件目录中的 `Config/DefaultUBotROS.ini` 仅保存重定向；项目设置保存在项目目录下的 `Config/DefaultUBotROS.ini`，两者是不同文件。
