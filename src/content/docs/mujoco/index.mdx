uBotMuJoCo 是规划中的物理插件，目前尚未发布。

<PackageStatus name="UBotMuJoCo" />

## 定位

uBotMuJoCo 计划为机械臂抓取等关节型机器人任务提供 MuJoCo 物理后端。MuJoCo 负责计算机器人运动，并将计算结果同步至 UE 组件，以供场景显示、传感器采样和 ROS 2 数据发布使用。

Chaos 仍是默认的物理引擎，不会被替换：MuJoCo 仅模拟绑定到该后端的物体，场景中的其他物体继续由 Chaos 模拟。[uBotPhysics](/physics/) 负责物体与后端的绑定关系以及步进调度，适用于未经修改的 UE 5.5。

在 uBot Manager 里它显示为「规划中」，按钮是「暂不可用」，现在不能安装。

## 计划提供的能力

| 能力标签 | 含义 |
| --- | --- |
| `Physics.MuJoCo` | 由 MuJoCo 计算一部分物体的物理，按仿真时钟步进，结果写回 UE |
| `Body.Articulated` | 关节型机器人：机械臂、足式机器人等，第一版只做这一类 |

计划的工作方式：

| 环节 | 做法 |
| --- | --- |
| 后端 | uBotMuJoCo 是 uBotPhysics 的一个物理后端：在 uBotPhysics 声明的扩展点 `UBotPhysics.Backend` 注册，使用时在绑定组件 `uBot Physics Binding` 的 `Backend` 里选它。每个组件只能绑定到一个后端 |
| 步进 | 由 uBotPhysics 按 uBotCore 的[仿真时钟](/concepts/clock-and-scheduling/)驱动，MuJoCo 用自己的固定步长追赶仿真时间，每帧可能执行多个物理步。暂停期间停止步进，恢复后不会执行暂停期间的物理步 |
| 每帧顺序 | 时钟推进 → 场景更新（后端接收场景时）→ MuJoCo 步进 → 位姿写回 UE 组件 → Chaos 模拟其余物体 → 传感器采样，传感器读到的总是这一帧算完的状态 |
| 写回 UE | 由 MuJoCo 计算的组件不再由 Chaos 模拟，只接收位姿；保留查询用的碰撞，相机仍可渲染该物体，激光雷达仍可通过碰撞查询检测该物体 |
| 场景 | uBotPhysics 0.1.0 把关卡里其余的碰撞体交给声明了场景能力的后端：Mobility 为 `Static` 或 `Stationary` 的是静态碰撞体，`Movable` 的是运动学物体，每帧更新位姿。uBotMuJoCo 声明这项能力后，MuJoCo 里的物体就能和 UE 里的地面、墙和桌子接触；地形、实例化静态网格和蒙皮网格不包含在场景几何导出范围内，见 [uBotPhysics](/physics/scene/) |
| 坐标 | MuJoCo 是右手系、Z 轴朝上、单位米，模型的 X 轴朝前时与 ROS 的 FLU 相同。因此可使用 uBotCore 的中立坐标转换约定（`UBot::RightHanded`，蓝图是 `UE To Right-Handed …` 节点），不经过 ROS，见[坐标系与单位](/concepts/coordinates-and-units/) |
| 模型 | 从 MJCF 或 URDF 导入，同时生成 UE 里的显示模型和 MuJoCo 模型 |

使用时有两条限制：

- 会互相碰撞的物体要交给同一个后端。比如机械臂和它要抓的物体都交给 MuJoCo；跨引擎只有单向作用：交给 MuJoCo 的物体在 Chaos 里是运动学体，能推动 Chaos 里的物体，Chaos 物体不会反向驱动 MuJoCo 物体。
- UE 里一次仍然只运行一个场景，大规模并行训练放在纯 MuJoCo 里做。同一份 MJCF 模型在 MuJoCo 里训练、在 UE 里加上画面和传感器验证，两边用的是同一个模型。

尚未确定：组件和蓝图类的名称与属性，关节级指令（位置、速度、力矩）的接口，uBotMuJoCo 是否声明场景能力、直接用 UE 里的地面和桌子作为 MuJoCo 的碰撞体，还是只用 MJCF 模型自带的，以及支持的 MuJoCo 版本。

## 与现有插件的关系

- uBotPhysics：按包索引，它依赖 uBotPhysics 0.1.x。“物理后端”扩展点 `UBotPhysics.Backend`、绑定组件、按仿真时钟步进和位姿写回都由 uBotPhysics 提供，uBotMuJoCo 只负责 MuJoCo 这一个后端；其他物理后端也通过该扩展点注册，见 [uBotPhysics](/physics/)。
- uBotCore：按包索引，它依赖 uBotCore 0.1.3 或更新的 0.1.x，用到里面的仿真时钟、执行器接口和坐标约定。
- uBotSensor：传感器默认从组件位姿计算速度和加速度，所以装在 MuJoCo 机器人上的传感器不用改。uBotSensor 0.1.2 起，位姿、里程计和 IMU 可以读刚体状态源给出的真值，见[读取刚体状态](/sensor/body-state/)。
- uBotROS：机器人实现 `UBot Velocity Commandable` 后，ROS 2 的 `cmd_vel` 就能驱动它，uBotROS 不用改，见[接收 cmd_vel](/ros/cmd-vel/)。
- uBotLearning：Learning Agents 在 UE 里训练；uBotMuJoCo 计划支持在独立 MuJoCo 环境中训练，再在 UE 场景中验证的流程。

## 发布前可以先怎么做

- 使用 Chaos 构建机器人（Physics Asset 和 Physics Constraint），在实现 `UBot Velocity Commandable` 的对象中编写控制逻辑，见[插件之间怎么对接](/concepts/interfaces/)。保持该指令接口后，后续切换物理后端时可继续使用现有的指令调用方式。
- 将传感器安装在机器人组件上，见[传感器通用用法](/sensor/basics/)。
- 对于需要在 MuJoCo 中验证接触行为的任务，可先独立运行 MuJoCo 并保留 MJCF 模型。后续导入流程以 uBotMuJoCo 发布时的说明为准。
- uBotMuJoCo 发布后，基于 Chaos 的现有机器人是否需要调整，以及具体迁移步骤，尚未确定。
