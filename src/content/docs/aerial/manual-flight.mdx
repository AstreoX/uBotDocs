`uBot Multirotor Manual Input` 将键盘和手柄输入转换为无人机指令，支持三种手动飞行模式，并随玩家控制对象切换操控的无人机。

## 快速用法

以下蓝图在每个 Tick 将当前摇杆输入值显示在屏幕上，以检查组件是否收到输入。三个示例蓝图的行为由组件实现，默认关闭 `Start with Tick Enabled`；在示例蓝图中使用 `Event Tick` 前，需要在「Class Defaults」中开启该属性，也可将以下逻辑放在其他 Actor 中：

```blueprint
caption: 每个 Tick 显示手动输入的前进量（-1 到 1）
nodes:
  T: AActor.ReceiveTick
  M: { var: ManualInput, class: UUBotMultirotorManualInputComponent }
  G: UUBotMultirotorManualInputComponent.GetAxes
  B: { ref: Break:FUBotManualFlightAxes, hideUnconnected: true }
  S: UKismetStringLibrary.Conv_DoubleToString
  P: UKismetSystemLibrary.PrintString
wires:
  - T.then -> P.execute
  - M.ManualInput -> G.self
  - G.ReturnValue -> B.UBotManualFlightAxes
  - B.Forward -> S.InDouble
  - S.ReturnValue -> P.InString
```

`Is Controlling` 返回此组件当前是否接管手动输入。通过 `Get Player Controller` 和 `Possess`，可将本地玩家的操控对象切换为另一架无人机：

```blueprint
caption: 让 Player 0 改为操控关卡里的物理无人机
nodes:
  A: AActor.ReceiveBeginPlay
  C: { ref: UGameplayStatics.GetPlayerController, set: { PlayerIndex: 0 } }
  D: { ref: UGameplayStatics.GetActorOfClass, set: { ActorClass: BP_UBotPhysicsDrone } }
  P: AController.Possess
wires:
  - A.then -> D.execute
  - D.then -> P.execute
  - C.ReturnValue -> P.self
  - D.ReturnValue -> P.InPawn
```

## 步骤

<Steps>

1. **添加组件**

   示例蓝图里的 `ManualInput` 就是这个组件。自定义无人机需要添加 `uBot Multirotor Manual Input`，所属的 Actor 必须是 Pawn。

2. **让玩家控制这架 Pawn**

   在「Details」面板把 `Auto Possess Player` 设为 Player 0，或者在蓝图里调用 `Possess`。组件只在本地玩家控制这架 Pawn 时接管输入，AI 控制器和远程控制器不触发它。

3. **选飞行模式**

   `Flight Mode` 要和无人机能接受的指令匹配，见下表。选中 `ManualInput`，可在「Details」面板的「Manual Input」类别下查看全部设置：

   ![ManualInput 组件的 Details 面板：Manual Input 下有 Take Control when Possessed、Flight Mode、各项满偏量和 Dead Zone，Custom 下是自定义键位的三项和 Mapping Priority](../../../assets/aerial/physics-manual-input.png)

4. **检查输入设置**

   工程的「Project Settings > Input > Default Player Input Class」需要设为 Enhanced Input 的玩家输入类，否则组件会记录一次错误日志，无人机不响应按键。

</Steps>

键位如下，输入动作和映射上下文在运行时创建，无需预先创建输入资产：

| 轴 | 键盘 | 手柄（模式 2） |
| --- | --- | --- |
| 前 / 后 | W / S | 右摇杆上 / 下 |
| 右 / 左 | D / A | 右摇杆右 / 左 |
| 上 / 下 | Space / Left Ctrl | 左摇杆上 / 下 |
| 偏航右 / 左 | E / Q | 左摇杆右 / 左 |

地面按普通碰撞面处理：无人机贴近地面时，可按 W / A / S / D 沿地面移动，按 Space 上升。

## 关键属性

`Flight Mode` 决定摇杆的含义：

| `Flight Mode` | 摇杆含义 | 发出的指令 | 示例里用它的无人机 |
| --- | --- | --- | --- |
| `Velocity` | 前后左右输入控制航向坐标系下的水平速度，上下输入控制升降速度，偏航轴控制偏航角速度 | 速度指令 | 导航、物理 |
| `Angle`（自稳） | 前后左右输入控制俯仰和横滚倾角，偏航轴控制航向变化，上下输入控制爬升率 | 姿态指令，未显式指定推力，以爬升率控制垂直运动 | 无（物理无人机可选） |
| `Rate`（特技） | 前后左右输入控制俯仰和横滚角速度，偏航轴控制偏航角速度，上下输入控制爬升率 | 角速度指令 | 裸机架 |

各输入轴达到最大偏转时，对应的控制量如下：

| 属性 | 默认值 | 作用 |
| --- | --- | --- |
| `Max Horizontal Speed Meters Per Second` | 5 m/s | `Velocity` 模式的水平速度 |
| `Max Vertical Speed Meters Per Second` | 2 m/s | 升降速度 |
| `Max Yaw Rate Degrees Per Second` | 90°/s | 偏航角速度 |
| `Max Tilt Degrees` | 30° | `Angle` 模式的倾角，范围 0 到 60 |
| `Max Body Rate Degrees Per Second` | 220°/s | `Rate` 模式的横滚、俯仰角速度 |
| `Dead Zone` | 0.15 | 摇杆死区，死区边缘重映射为 0，范围 0 到 0.9 |
| `Take Control when Possessed` | 开 | 关闭后组件不接管输入 |

两个水平输入轴组成的向量长度限制为 1，因此斜向输入不会产生更高的目标水平速度。

## 输出与事件

- 控制期间组件每帧发一条指令。
- 控制结束时，`Velocity` 模式发 `Stop Motion`，无人机刹停并悬停。`Angle` 和 `Rate` 模式发 `Release Attitude Command`，释放姿态指令，接下来由无人机的 `Command Loss Action` 决定，默认是 `Hover`（刹停并悬停），见[物理无人机的指令与控制模式](/aerial/dynamics/#关键属性)。
- 同时有其他发送方（例如 ROS）时，最后到达的指令生效。

## 注意事项

- `Angle` 和 `Rate` 模式下，右摇杆向右是向右倾或横滚，向前是机头下俯，偏航轴向右是向右偏航。
- 导航无人机没有姿态接口，选 `Angle` 或 `Rate` 时日志警告一次。
- 示例蓝图的相机挂在弹簧臂上：臂长 120 cm，俯仰 −15°，只继承机体的偏航，所以物理无人机倾斜、翻滚时视角不会随俯仰和横滚变化。
- 使用已发布的 0.1.1 时，若无人机初始位置贴近地面，导致弹簧臂因碰撞检测而缩短、相机靠近机体，在示例蓝图中将 `CameraBoom` 的相对位置 Z 设为 20 cm。保持 12 cm 的 `Probe Size` 和 `Do Collision Test` 开启；0.1.2 开发版已将这项抬高设为默认值。
- 自定义键位时，需要设置 `Custom Mapping Context`、`Custom Move Action`（前、右、上三个轴）和 `Custom Yaw Action`，映射上下文要映射这两个动作；未指定自定义映射时，使用内置键位。
