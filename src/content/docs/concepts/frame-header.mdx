传感器帧头（Frame Header）记录采样标识、序号、时间戳和状态，可用于检查数据有效性并识别新样本。

## 帧头字段

每次采样都会生成一个帧头（[`UBot Frame Header`](/reference/ubotcore/structs/fubotframeheader/)），与传感器数据一同通过事件和 `Get Latest …` 节点提供。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `Sensor Id` | String | 传感器标识；留空时使用组件名称 |
| `Frame Id` | String | 传感器所在坐标系的名称；留空时等于 `Sensor Id` |
| `Sequence` | Integer64 | 帧序号，由每个传感器组件独立维护，每次采样递增 1 |
| `Timestamp Seconds` | Float (double) | 采样时的仿真时间，单位秒 |
| `Valid` | Boolean | 只有 `Status` 为 `Valid` 时为 true |
| `Status` | EUBot Sample Status | 本次采样的结果，见下表 |

`Sensor Id` 和 `Frame Id` 的取值规则，见[标识与命名](/concepts/identity/)。

## 状态码

状态码（`Status`）的类型是 [`EUBot Sample Status`](/reference/ubotcore/enums/eubotsamplestatus/)：

| `Status` | 出现条件 |
| --- | --- |
| `Valid` | 正常样本，数据可以直接使用 |
| `Warming Up` | 惯性测量单元（IMU）和里程计通过相邻样本的差分计算速度等物理量，启动或重置后可能因历史不足而输出预热样本；直接读取刚体状态时（见[读取刚体状态](/sensor/body-state/)）预热阶段更短 |
| `Invalid Delta Time` | 与上次采样的间隔不合理，历史被清空：IMU 为 0 或超过 `Max Sample Delta Seconds`；里程计小于 `Minimum Valid Delta Seconds`（默认 0.0001 s）或超过 `Maximum Valid Delta Seconds`；两个上限默认都是 0.5 s |
| `Teleport Detected` | 两次采样间的位移或转角超过阈值（IMU 和里程计默认 5 m 或 120°），视为瞬移，历史被清空 |
| `Disabled` | `Sensor Enabled` 为 false 时手动调用 `Sample Sensor` 得到的样本 |
| `Error` | 采样出错，例如激光雷达扫描范围无效；帧头默认也采用该状态，表示尚未执行采样 |

各传感器输出状态码的具体条件见相应功能说明，例如 [IMU 传感器](/sensor/imu/)。

## 判断一帧能不能用

无效样本同样会触发采样事件。使用速度、加速度等差分计算结果前，应检查帧头的 `Valid` 字段：

```blueprint
caption: 只在有效样本时继续
nodes:
  A: { ref: UUBotSensorComponent.OnSensorSampled, component: IMU }
  B: { ref: Break:FUBotFrameHeader, hideUnconnected: true }
  C: K2Node_IfThenElse
wires:
  - A.then -> C.execute
  - A.Header -> B.UBotFrameHeader
  - B.bValid -> C.Condition
```

差分计算得到的速度和加速度仅在有效样本中提供有效值。

## 用 Sequence 判断是否有新数据

通过事件接收数据时，每个样本只触发一次对应事件，无需比较 `Sequence`。在 `Event Tick` 中通过 `Get Latest …` 轮询时，同一样本可能被多次读取；只有当前 `Sequence` 与上次已处理样本的序号不同时，才应作为新样本处理：

```blueprint
caption: 轮询时，只在 Sequence 变化时处理样本
nodes:
  T: AActor.ReceiveTick
  V: { var: IMU, class: UUBotImuSensorComponent }
  G: UUBotSensorComponent.GetLatestFrameHeader
  B: { ref: Break:FUBotFrameHeader, hideUnconnected: true }
  N: UKismetMathLibrary.NotEqual_Int64Int64
  C: K2Node_IfThenElse
wires:
  - T.then -> C.execute
  - V.IMU -> G.Target
  - G.ReturnValue -> B.UBotFrameHeader
  - B.Sequence -> N.A
  - N.ReturnValue -> C.Condition
notes:
  N: "将 `B` 连接到一个 Integer64 变量，用于保存上次已处理样本的序号，初始值为 0。"
  C: 仅在 True 分支处理新样本。
```

完成样本处理后，将保存序号的变量更新为当前 `Sequence`，供下一次轮询比较。

序号的规则：

- 每个传感器组件的第一个样本的序号为 1，此后每次采样递增 1，包括无效样本和手动调用 `Sample Sensor` 生成的样本。
- 调用 `Stop Sensor` 后再次调用 `Start Sensor`，不会将序号重置为 1。
- 两次读取的序号之差大于 1，表示读取方遗漏了中间样本。
- 因帧率低而跳过的计划采样时刻不会递增序号，这些时刻仅计入 `Get Dropped Sample Count`。
