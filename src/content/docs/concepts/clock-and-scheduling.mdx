uBot 使用统一的仿真时间安排传感器采样，并通过采样调度规则处理帧率与目标采样频率不一致的情况。

## 仿真时间从哪里来

所有 uBot 时间戳均采用统一的仿真时间（simulation time），即世界（World）的游戏时间（`UWorld::GetTimeSeconds()`）。仿真时间在世界暂停时停止推进，其推进速率受时间膨胀影响，与现实时间（wall-clock time）不同。

| 量 | 含义 | 读取方式 |
| --- | --- | --- |
| 仿真时间 | World 的游戏时间，单位秒；每次新的 PIE 或 Game 会话从 0 开始 | `Get Sim Time Seconds`；帧头的 `Timestamp Seconds` |
| 仿真帧号 | 游戏时间已推进的世界更新（world tick）次数；暂停时停止增长 | `Get Sim Frame` |
| ROS 的 `/clock` | uBotROS 发布的仿真时间，采用相同的时间基准 | [TF 与 /clock](/ros/tf-and-clock/) |

两个 `Get Sim …` 节点均由 `UBot Clock Subsystem` 提供，用法见 [uBotCore 的仿真时钟](/core/clock/)。

## 固定步长、暂停与单步

时钟子系统（`UBot Clock Subsystem`）仅存在于游戏（Game）世界和编辑器内运行（PIE，Play In Editor）世界中，蓝图节点在「uBot > Clock」类别下。

| 节点 | 作用 |
| --- | --- |
| `Set Fixed Time Step` | 启用或关闭引擎固定步长（fixed time step）。`Step Hz` 默认 60，限制在 1 到 1000 Hz |
| `Pause Simulation`、`Resume Simulation` | 暂停和恢复游戏，同时取消尚未完成的单步任务 |
| `Step Simulation` | 恢复运行恰好 `Num Frames`（默认 1）个 world tick，然后再暂停 |
| `Get Remaining Step Frames` | 返回当前单步任务剩余的帧数 |

- 固定步长让引擎每帧使用固定的时间增量 1 / `Step Hz`。该设置由整个进程共享：首次修改时记录原始值，最后一个曾修改该设置的时钟销毁时恢复原始值。
- 暂停操作需要本地玩家控制器（PlayerController），并要求游戏模式（GameMode）允许暂停。操作未达到目标状态时，日志会输出 `LogUBot` 警告；编辑器的 PIE 暂停功能会持续保持世界的暂停状态，此时无法通过时钟子系统恢复运行。
- `Step Simulation` 在 `Num Frames` 小于 1 或无法取消暂停时返回 false。单步进行中再次调用，剩余帧数累加。

暂停时仿真时间不前进，传感器也不采样。启用固定步长后，每个单步帧按 1 / `Step Hz` 秒的固定时间增量推进。

若需要在每个 Game 或 PIE 世界启动时自动启用固定步长，可在「Project Settings > Plugins > uBot Core」的「Clock」分类中勾选 `Use Fixed Time Step`（默认 false），并设置 `Fixed Time Step Hz`（默认 60 Hz）。取消勾选不会关闭已经启用的固定步长。

## 采样调度

采样调度器（sample scheduler）根据 `Update Rate Hz`（0.1 到 240 Hz）在仿真时间轴上安排传感器采样，规则如下：

- `Start Sensor` 立即采样一次，第一个计划时刻是启动时刻加 1 / `Update Rate Hz`。
- 计划采样时刻按等间隔网格排列：第一个计划时刻加 k / `Update Rate Hz`，其中 k 为从 0 开始的采样序号。调度器直接根据序号计算时刻，避免逐次累加造成的长期时间漂移。
- 每帧最多采样一次。一帧跨过多个时刻时只采样一次，其余时刻计入 [`Get Dropped Sample Count`](/reference/ubotsensor/uubotsensorcomponent/#GetDroppedSampleCount)，`Start Sensor` 时清零。
- 运行中调用 `Set Update Rate Hz` 仅修改采样间隔，下一次采样时刻不变。
- 暂停时不采样。

采样调度不使用循环定时器，因此即使单帧耗时较长，也不会在同一帧内生成多个时间戳相同的定时样本。

因此，帧率低于 `Update Rate Hz` 时，实际采样频率等于帧率。例如 0.5 s 的单帧在 100 Hz 下只采样一次，并跳过 49 个采样时刻。

时间戳采用实际执行采样时所在帧的仿真时间，而非网格上的计划采样时刻，因此定时样本的时间戳严格递增。

## 固定步长的多步消费（0.1.3 起）

传感器每帧最多采样一次，而采用固定步长的物理模拟可能需要在一帧内执行多个已到期的步进。uBotCore 0.1.3 起，采样调度器 `FUBotSampleScheduler` 为此提供 `ConsumeDueSteps`；该函数仅支持 C++ 调用，没有对应的蓝图节点。

`ConsumeDueSteps(NowSeconds, MaxSteps, OutFirstDueSeconds)` 的规则是：

- 统计从下一个计划采样时刻开始、不晚于 `NowSeconds` 的到期时刻，返回不超过 `MaxSteps` 的步数。
- 调用后，下一个计划采样时刻推进到 `NowSeconds` 之后。超过 `MaxSteps` 限制的到期时刻会被跳过并计入丢弃计数（`GetDroppedSampleCount`），后续调用不会补执行这些步进。
- 可选输出参数 `OutFirstDueSeconds` 返回第一个到期时刻；其后各步的计划时刻为该值加 k × `GetIntervalSeconds()`，其中 k 从 0 开始。
- `MaxSteps` 小于 1、`NowSeconds` 不是有限数或早于下一个采样时刻、调度器尚未初始化时，返回 0，`OutFirstDueSeconds` 不变。

当一帧跨过多个计划时刻时，`ConsumeDueSteps` 与 `ConsumeDue` 的行为差异如下：

| 调用 | 一帧跨过 4 个时刻 | 丢弃计数 |
| --- | --- | --- |
| `ConsumeDue` | 返回 true 一次，只采样一次 | 加 3 |
| `ConsumeDueSteps`，`MaxSteps` 为 1000 | 返回 4，调用方执行 4 个步进 | 不变 |
| `ConsumeDueSteps`，`MaxSteps` 为 2 | 返回 2，调用方只执行最早的 2 个步进 | 加 2 |

例如，某个 100 Hz 调度器的下一个计划采样时刻为 1.00 s，当前仿真时间为 1.035 s：`ConsumeDueSteps` 返回 4，对应 1.00、1.01、1.02 和 1.03 s，下一个采样时刻变成 1.04 s。

uBotPhysics 使用该函数，使各物理后端按各自的固定步长推进到不超过当前仿真时间的最近步进时刻，见 [uBotPhysics 的步进与时序](/physics/stepping/)。
